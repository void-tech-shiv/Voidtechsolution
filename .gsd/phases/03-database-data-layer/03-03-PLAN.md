# Plan 03-03: Environment Configuration & Credential Readiness

## Objective
Audit, standardize, and harden the project's environment variable architecture so the user can securely enter their real application credentials, PostgreSQL connection details, administrator credentials, email address, SMTP app password, and required API keys locally without exposing secrets.

Strictly do NOT start Phase 4 or implement homepage features.

## Scope of Execution

### Task 1: Audit and Inventory Environment Variables
- Identify every variable consumed across the application:
  - Database: `DATABASE_URL`, `DIRECT_URL`
  - Authentication: `AUTH_SECRET`, `OTP_PEPPER_SECRET`
  - Admin Bootstrap: `ADMIN_EMAIL`, `ADMIN_PASSWORD`
  - Nodemailer SMTP: `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM_NAME`, `SMTP_FROM_EMAIL`, `ADMIN_ALERT_EMAIL`
  - Application Runtime: `NEXT_PUBLIC_SITE_URL`, `NODE_ENV`
- Safely deprecate/remove obsolete Phase 1 variables (`EMAIL_PROVIDER_API_KEY`, `EMAIL_FROM`, `ENQUIRY_NOTIFICATION_RECIPIENT`).

### Task 2: Environment Validation & Production Hardening
- Create centralized schema validation in `src/config/env.ts` with strict production mode constraints.
- In production (`NODE_ENV === "production"`), enforce that development dummy passwords or missing SMTP credentials produce clear, safe errors.
- Ensure `src/server/email/config.ts` enforces production-safe checks.
- Add password hashing helper (`scrypt` / PBKDF2) for secure admin bootstrap password handling in `src/server/security/password.ts`.
- Update `prisma/seed.ts` to securely hash `ADMIN_PASSWORD` if provided.

### Task 3: Local Credential Entry Preparation (.env & .env.example)
- Generate a 256-bit random `AUTH_SECRET` and `OTP_PEPPER_SECRET` using a cryptographically secure generator.
- Update `.env.example` with clear documentation, placeholders, and setup instructions.
- Prepare local `.env` with clearly marked placeholders ready for user entry.
- Verify `.env` is ignored by `.gitignore` and `git check-ignore`.

### Task 4: Documentation Synchronization
- Update `docs/EMAIL_SYSTEM.md`, `docs/SECURITY.md`, `docs/DEPLOYMENT.md`, `docs/PROJECT_STATUS.md`, `docs/ARCHITECTURE.md`.
- Document setup instructions for PostgreSQL (Neon / Supabase / RDS), Nodemailer SMTP (Gmail App Password, Mailgun, SendGrid), and credential rotation.
- Never document actual secrets.

### Task 5: Testing & Empirical Verification
- Author `tests/unit/env.test.ts` verifying Zod schema validation, production mode constraints, and password hashing/verification.
- Run complete test suite (`vitest run` — all tests passing).
- Run `tsc --noEmit` (0 errors).
- Run `next lint` (0 warnings/errors).
- Run `next build` (clean compilation).

### Task 6: Strict Stop Condition
- Verify Phase 4 has NOT started.
- Commit safe configuration and documentation changes to `session/phase-3-env-readiness`.
- Report findings and await user input for entering credentials.
